# JIGᶻ AGENT Store — Cloudflare

ระบบหน้าร้านและหลังบ้านสำหรับ JIGᶻ AGENT บน Cloudflare Workers + D1

## ฟังก์ชันรุ่น 5.13.0 — ระบบชำระด้วยเครดิตร้าน

- OWNER สร้างรหัสเครดิต ผูก User ID ระบุชื่อผู้เครดิตและยอดเครดิต
- รหัสใช้ได้เฉพาะบัญชีลูกค้าที่ผูกไว้ และจัดเก็บแบบแฮช
- ระบบตรวจยอดคงเหลือและหักเครดิตพร้อมสร้างออเดอร์
- ยกเลิกออเดอร์แล้วคืนยอดเครดิตอัตโนมัติ พร้อมประวัติ Audit
- OWNER แก้ไขวงเงิน ระงับ หรือลบบัญชีเครดิตได้จากหน้าเครดิต ฝาก / ถอน

## ฟังก์ชันรุ่น 5.12.3 — สีสถานะออเดอร์ครบ 9 ขั้นตอน

- `NEW` สีส้ม, `ACCEPTED` สีขาว, `PENDING_PAYMENT` สีฟ้าอ่อน
- `PAID` สีน้ำเงินพร้อมสัญลักษณ์เงินบาท, `PACKING` สีชมพู, `PACKED` สีม่วงเข้ม
- `SHIPPED` สีเหลือง, `COMPLETED` สีเขียวพร้อมเครื่องหมายถูก, `CANCELLED` สีแดง
- ใช้รูปแบบเดียวกันทั้งหน้าลูกค้าและ Command Center

## ฟังก์ชันรุ่น 5.12.1 — Mobile Data View, POS Cart & SEO

- ตารางข้อมูลหลังบ้านบนมือถือแสดงเป็นการ์ดเต็มความกว้าง ไม่ต้องเลื่อนซ้าย–ขวา
- POS มือถือใช้ตะกร้าแบบเลื่อนขึ้น พร้อมจำนวนรายการและยอดรวมบนปุ่มลอย
- ออเดอร์ สินค้า ลูกค้า ตัวแทน ค่าคอม โปรโมชั่น และเครดิตมีตัวกรองข้อมูล
- เพิ่ม canonical, Open Graph, Twitter Card, OnlineStore JSON-LD และเนื้อหาเกี่ยวกับร้านค้าปลีกสมุนไพรที่ผู้ใช้มองเห็นได้
- มีปุ่มแชร์ร้านผ่านเมนูแชร์ของโทรศัพท์ และไฟล์ `SOCIAL-SEO-PLAN.md`

## ฟังก์ชันรุ่น 5.10.0 — Internal Device Access

- อุปกรณ์ใหม่ส่งคำขอสิทธิ์จากหน้า `/admin` ได้โดยไม่ต้องใช้ Cloudflare Access
- OWNER อนุมัติหรือปฏิเสธอุปกรณ์จากหน้า **ผู้ดูแลระบบ**
- เมื่ออนุมัติแล้ว อุปกรณ์เดิมจะเข้าใช้งานหลังบ้านได้อัตโนมัติ
- การถอดสิทธิ์เป็นผู้ใช้ทั่วไปมีผลทันที เพราะทุก API ตรวจบทบาทจาก D1 ทุกครั้ง
- หน้า Health แสดง **สิทธิ์หลังบ้าน: อนุมัติอุปกรณ์** และจำนวนอุปกรณ์ที่รอตรวจ โดยไม่มี `ACTION_REQUIRED`

## ฟังก์ชันรุ่น 5.9.0 — Sales Control & Approval

- แยกโหมดเซลล์ออกจากแอดมินโดยใช้ User ID ที่เชื่อมกับตัวแทนประเภท `SALES`
- เซลล์เปิดได้เฉพาะ POS และหน้า `ยอดขายของฉัน`; API ฝั่ง Worker ปฏิเสธ Dashboard การเงิน สต๊อก ผู้ใช้ และการตั้งค่าระบบ
- ราคาพิเศษที่ส่วนลดหรือกำไรเกินขอบเขตจะส่งให้ OWNER หลักอนุมัติ ก่อนสร้างบิลและตัดสต๊อก
- OWNER ตั้งค่าส่วนลดสูงสุดและกำไรขั้นต่ำของบิลเซลล์ได้จากหน้าตั้งค่าระบบ
- เพิ่มใบสรุปค่าคอมที่พิมพ์หรือบันทึก PDF ได้ พร้อมยอดขาย ทุน FIFO กำไร และสถานะจ่าย
- เมื่อบิลที่จ่ายค่าคอมแล้วถูกลบ ระบบสร้างยอดกลับรายการ และหักจากค่าคอมรอบถัดไปโดยไม่แก้ประวัติเดิม

## ฟังก์ชันรุ่น 5.8.0 — Sales Workspace

- เพิ่มเมนู `ยอดขายของฉัน` สำหรับผู้ใช้ที่เชื่อมเป็นเซลล์โดยเฉพาะ
- แสดงจำนวนบิล ยอดขายวันนี้ ยอดขายเดือนนี้ ค่าคอมรอจ่าย และค่าคอมที่จ่ายแล้ว
- แสดงประวัติบิลพร้อมต้นทุนจริง ฐานกำไร อัตราค่าคอม และสถานะการจ่าย
- API ตรวจ User ID ฝั่ง Worker แล้วกรองเฉพาะข้อมูลของเซลล์คนนั้น ไม่รับรหัสเซลล์จากเบราว์เซอร์เป็นตัวกำหนดสิทธิ์
- เมนูนี้จะปรากฏอัตโนมัติหลัง OWNER เชื่อม User ID กับตัวแทนประเภท `SALES`

## ฟังก์ชันรุ่น 5.7.3 — Sales Auto-Commission

- ผู้ใช้ที่แต่งตั้งเป็น ADMIN และเชื่อมกับตัวแทนประเภท `SALES` จะได้รับรหัสเซลล์ประจำตัวใน POS อัตโนมัติ
- เซลล์คีย์บิลโดยไม่ต้องกรอกรหัส ระบบ Worker ผูกออเดอร์กับ User ID และรหัสเซลล์ฝั่งเซิร์ฟเวอร์
- ป้องกันการเปลี่ยนหรือสวมรหัสเซลล์ผ่านข้อมูลที่ส่งจากเบราว์เซอร์
- สร้างรายการค่าคอมทันทีจากราคาขายจริง ลบต้นทุน FIFO และส่วนหักต่าง ๆ โดยจ่ายเข้ากระเป๋าเมื่อออเดอร์สำเร็จตามรอบวันอาทิตย์

วิธีตั้งค่า: OWNER แต่งตั้ง User ID เป็น ADMIN จากเมนูผู้ดูแลระบบ จากนั้นไปเมนูตัวแทน สร้างหรือแก้รายการประเภท `SALES` แล้วเชื่อม User ID เดียวกัน เมื่อผู้ใช้นั้นเปิด POS ระบบจะแสดงชื่อ รหัส และอัตราคอมอัตโนมัติ

## ฟังก์ชันรุ่น 5.7.2 — Flexible POS Pricing

- แอดมินกำหนดราคาขายต่อแพ็กแยกเป็นรายบิลได้จากตะกร้า POS
- ราคาพิเศษใช้กับออเดอร์นั้นเท่านั้น ไม่แก้ราคามาตรฐานและไม่กระทบหน้าลูกค้า
- ใบเสร็จ รายงานยอดขาย กำไร และค่าคอมใช้ราคาที่ขายจริง โดยต้นทุนยังคำนวณจาก FIFO
- Audit Log บันทึกราคาเดิม ราคาที่ขายจริง ผู้ทำรายการ สินค้า และขนาดที่เปลี่ยน

## ฟังก์ชันรุ่น 5.7.1 — Production POS

- หน้า POS พิมพ์จำนวนแพ็กได้โดยตรงทั้งก่อนเพิ่มสินค้าและในรายการขาย
- ยังคงใช้ปุ่ม − / + ได้ พร้อมจำกัดจำนวนสูงสุดตามเรทราคาและสต๊อกที่เหลือ
- คำนวณยอดทันทีและตรวจสต๊อกซ้ำที่ Worker ก่อนตัดยอดจริง

## ฟังก์ชันรุ่น 5.7.0 — Production Safety

- ป้องกันการกดสั่งซื้อซ้ำด้วย Idempotency Key โดยคืนออเดอร์เดิมแทนการตัดสต๊อกซ้ำ
- จองสต๊อกออเดอร์ออนไลน์ตามเวลาที่ตั้งค่า (ค่าเริ่มต้น 15 นาที) และคืนสต๊อกอัตโนมัติเมื่อหมดเวลา
- เพิ่มคำยืนยันข้อจำกัดด้านอายุ สุขภาพ และกฎหมายก่อนสร้างออเดอร์
- เพิ่ม Health Center, System Alerts, คำขออนุมัติรายการเสี่ยงสูง และไฟล์สำรอง JSON
- ล็อก Audit Log ไม่ให้แก้ไขหรือลบ พร้อมตรวจ Access JWT ด้วยลายเซ็น RS256
- เพิ่ม Cron ทุก 5 นาทีสำหรับงานบำรุงรักษา และคงรอบจ่ายค่าคอมทุกวันอาทิตย์ 17:00 น. ประเทศไทย
- เพิ่มชุดทดสอบ API/D1 จริงสำหรับการสร้างออเดอร์ ตัด/คืนสต๊อก ออเดอร์ซ้ำ สิทธิ์ OWNER และสำรองข้อมูล

- อัปเกรดเอฟเฟกต์เพิ่มสินค้าลงตะกร้าเป็น JIGᶻ Warp: วงแหวนวาร์ป ดาวเคราะห์ JIGᶻ เส้นพลังงาน ดาวหลากสี และคลื่นกระแทกที่ตะกร้า
- สีเอฟเฟกต์สุ่มจากชุดสีแบรนด์ทุกครั้ง พร้อมแรงสั่นเบาบนอุปกรณ์ที่รองรับ และลดการเคลื่อนไหวตามการตั้งค่าระบบของผู้ใช้

- เพิ่มระบบเปลี่ยนภาษาทั้งหน้าลูกค้า หลังบ้าน และคู่มือ: ไทย English และ中文
- จดจำภาษาที่เลือกในอุปกรณ์ พร้อมเปลี่ยนรูปแบบวันที่ เวลา และสกุลเงินตามภาษา
- แปลเฉพาะข้อความควบคุมของระบบ โดยคงชื่อแบรนด์ ชื่อสินค้า รายละเอียดสินค้า ชื่อบุคคล รหัส และข้อมูลที่กรอกจากฐานข้อมูลไว้ตามต้นฉบับ

- เพิ่มหน้าคู่มือการใช้งานภาษาไทยที่ `/guide.html` พร้อมสารบัญ ขั้นตอนสั่งซื้อ ชำระเงิน ติดตามพัสดุ และข้อควรระวัง
- เพิ่มปุ่ม `คู่มือใช้งาน` บนหน้าแรก รองรับมือถือ แท็บเล็ต และคอมพิวเตอร์

- ตั้งค่าข้อความหน้าแรก สี ธีม ภาพเคลื่อนไหว ช่องทางชำระ ยอดขั้นต่ำ สต๊อกต่ำ ข้อมูลติดต่อ และบัญชีรับเงินจากหลังบ้าน
- ตรวจนับสต๊อกรายสัปดาห์ พร้อมปรับยอดจริงและเก็บชื่อผู้ตรวจ
- ลบออเดอร์แบบคืนสต๊อก ซ่อนจากรายงานปกติ และเก็บชื่อผู้ลบใน Audit
- POS แสดงสินค้า เรทราคา และสต๊อกในรูปแบบเดียวกับหน้าลูกค้า
- ลูกค้าเปลี่ยนรูปบัญชีและแลกของรางวัลด้วยพอยส์ได้
- หลังบ้านเพิ่ม แก้ไข ปิด และลบของรางวัล พร้อมกำหนดรูป แต้ม และจำนวนคงเหลือ

- OWNER ลบออเดอร์ที่สำเร็จหรือยกเลิกแล้วออกจากหน้าทำงานได้ พร้อมระบุเหตุผลและยืนยันสองครั้ง
- ใช้การลบแบบปลอดภัย: ซ่อนออเดอร์จากหน้าทำงาน แต่เก็บรายการสินค้า การเงิน ค่าคอม และ Audit เดิมไว้
- เพิ่มปุ่มลัด `สร้างออเดอร์`, `แต่งตั้งผู้ดูแล`, `เพิ่มตัวแทน` และ `สร้างโปรโมชั่น` ในหัวข้อหน้าที่เกี่ยวข้อง

- ปิดเรทราคาที่จำนวนคงเหลือไม่ถึง และคำนวณจำนวนแพ็กสูงสุดตามสต็อกจริง
- ตรวจสต็อกรวมของสินค้าชนิดเดียวกันทุกเรทในตะกร้า ก่อนเข้าหน้าชำระเงินและก่อนสร้างออเดอร์
- ป้องกันการเพิ่มจำนวนด้วยปุ่ม `+` เมื่อสต็อกไม่พอ พร้อมตรวจซ้ำฝั่งเซิร์ฟเวอร์และ FIFO

- เพิ่มตัวสร้างเรทราคามาตรฐาน `1G / 10G / 30G / 50G / 100G / 500G / 1000G` ในปุ่มเดียว
- เปลี่ยนการกรอกราคาตามขนาดจาก JSON เป็นแถวจำนวนและราคารวม พร้อมตรวจช่องซ้ำหรือข้อมูลไม่ครบ
- หน้าร้านแสดงป้ายขนาดที่มีจำหน่ายบนการ์ดสินค้า และแสดงเรทแบบ `1G`, `10G` ในเมนูเลือกสินค้า

- ใส่ชื่อกำกับและคำอธิบายทุกช่องในฟอร์มเพิ่ม/แก้ไขสินค้า พร้อมตัวอย่างการกรอกสต็อก ต้นทุน และราคาตามขนาด

- แยก OWNER หลัก 1 คนและ OWNER รองสูงสุด 4 คน โดยมีตัวนับจำนวนและป้ายสิทธิ์ชัดเจน
- OWNER ทุกคนส่งคำขอลบ OWNER รองได้ แต่จะลบจริงเมื่อ OWNER หลักกดยืนยันเท่านั้น และ OWNER หลักถูกป้องกันไม่ให้ลบ
- เพิ่มประวัติคำขอ อนุมัติ/ปฏิเสธ และ Audit สำหรับการแต่งตั้งหรือลบ OWNER ทุกขั้นตอน
- เพิ่มภาพเคลื่อนไหวอวกาศแบบเบา ดาวกะพริบ แสงลอย และดาวเคราะห์ลอยช้าโดยไม่บังเนื้อหา
- ปรับ Responsive UI/UX สำหรับมือถือจอเล็ก จอพับ แท็บเล็ต แนวนอน และ Safe Area พร้อมรองรับ Reduce Motion

- ปิดยอดรายวันและรายเดือนตามเวลาไทย พร้อม Snapshot รายรับ ต้นทุนจริง FIFO กำไร ค่าคอม เงินสด/COD และเครดิตฝากถอน
- บันทึกเงินสดนับจริงและแสดงส่วนต่าง เปิดดู พิมพ์ หรือบันทึกรายงานเป็น PDF ได้
- OWNER ลบลูกค้าหรือผู้ดูแลระบบได้แบบปลอดภัย โดยเก็บออเดอร์และ Audit เดิมไว้ ยกเลิก Session และป้องกันการลบ OWNER
- บล็อกการลบผู้ใช้ที่ยังมีเครดิตหรือคำขอฝากถอนค้างตรวจ

- กระเป๋าเครดิตแยกตาม User ID อัตโนมัติ ลูกค้าดูยอด เติมเครดิต แนบสลิป ขอถอน และดูประวัติธุรกรรมได้
- ตรวจสลิปธนาคารด้วย EasySlip API v2 โดยตรวจยอดเงิน บัญชีผู้รับ และสลิปซ้ำก่อนเพิ่มเครดิต
- หาก EasySlip ยังไม่ได้ตั้งค่า โควตาหมด หรือผู้ให้บริการไม่พร้อม ระบบจะพักคำขอไว้ให้แอดมินตรวจ ไม่เพิ่มเครดิตอัตโนมัติ
- หน้า `เครดิต ฝาก / ถอน` ในหลังบ้านสำหรับเปิดดูสลิป อนุมัติ/ปฏิเสธคำขอ และยืนยันการโอนถอนเงิน
- เชื่อม User ID ของลูกค้ากับตัวแทนจำหน่ายหรือเด็กส่งยอด เพื่อรับค่าคอมเข้ากระเป๋าโดยไม่ต้องล็อกอิน

## Deploy ผ่าน GitHub

1. อัปโหลดไฟล์ทั้งหมดในชุดนี้ไว้ที่รากของ Repository `Jigz-store`
2. ตั้ง Build command เป็น `npm install`
3. ตั้ง Deploy command เป็น `npx wrangler deploy`
4. Push เข้า branch `main` แล้ว Cloudflare จะ Deploy อัตโนมัติ

ระบบผูก D1 ด้วยตัวแปร `DB` และสร้างตารางที่จำเป็นอัตโนมัติเมื่อเรียก API ครั้งแรก

รุ่น 5.10.0 เพิ่มการอนุมัติอุปกรณ์แอดมินภายในระบบ ส่วนรุ่น 5.9.0 เพิ่มขอบเขตสิทธิ์เซลล์ การอนุมัติราคาพิเศษ ใบสรุปค่าคอม และการกลับรายการค่าคอมแบบตรวจสอบย้อนหลังได้

## ตั้งค่าก่อนเปิดใช้งานจริง

1. Deploy รุ่นนี้และเปิด `/api/health` ให้แน่ใจว่า `ok` เป็น `true` และ `database` เป็น `connected`
2. อุปกรณ์ OWNER เดิมเปิด `/admin` และคงข้อมูลเว็บไซต์ของเบราว์เซอร์ไว้
3. อุปกรณ์แอดมินเครื่องใหม่เปิด `/admin` แล้วกด **ส่งคำขอสิทธิ์แอดมิน**
4. OWNER เปิดเมนู **ผู้ดูแลระบบ → คำขอเข้าใช้งานหลังบ้าน** ตรวจรหัสอุปกรณ์ แล้วกดอนุมัติหรือปฏิเสธ
5. ถ้าใช้ตรวจสลิป ให้เพิ่ม Secret `EASYSLIP_API_KEY` และทดสอบด้วยสลิปจริงหนึ่งครั้ง
6. เปิด `/admin` → `Health Center` ตรวจ EasySlip, Push, ออเดอร์ค้าง และอุปกรณ์รออนุมัติก่อนรับออเดอร์จริง
7. กด `ดาวน์โหลด Backup` และเก็บไฟล์แรกไว้ในพื้นที่ที่ OWNER หลักเข้าถึงได้

ระบบรุ่นนี้ไม่จำเป็นต้องใช้ Cloudflare Access และไม่ต้องตั้ง `ADMIN_ACCESS_REQUIRED`, `TEAM_DOMAIN` หรือ `POLICY_AUD` ลูกค้าหน้าร้านยังได้รับ User ID รายอุปกรณ์อัตโนมัติและไม่ต้องเข้าสู่ระบบ

## เปิดตรวจสลิป EasySlip

1. ใน EasySlip Developer ให้สร้าง API key และเพิ่มบัญชีธนาคารผู้รับเงินของร้านให้กับแอป/สาขาที่ใช้งาน
2. ไปที่ Cloudflare Worker → `Settings` → `Variables and Secrets`
3. เพิ่มตัวแปรแบบ **Secret** ชื่อ `EASYSLIP_API_KEY` แล้ววาง API key เป็นค่า
4. Deploy ใหม่หนึ่งครั้ง จากนั้นลองเติมเครดิตด้วยสลิปจริงที่ยอดตรงกัน

ห้ามใส่ API key ใน GitHub, `wrangler.jsonc`, JavaScript ฝั่งเบราว์เซอร์ หรือส่งคีย์ในแชต ระบบจะส่งรูปสลิปจาก Worker ไปยัง `POST https://api.easyslip.com/v2/verify/bank` เท่านั้น

การถอนเครดิตเป็นคำขอแบบตรวจสอบโดยแอดมิน: ระบบกันยอดทันที แต่แอดมินต้องโอนเงินผ่านธนาคารจริงก่อนกดอนุมัติ ระบบไม่ได้สั่งโอนเงินจากบัญชีธนาคารให้อัตโนมัติ

## รอบจ่ายค่าคอม

Cloudflare Cron Trigger ตั้งเป็น `0 10 * * SUN` หรือทุกวันอาทิตย์ 10:00 UTC / 17:00 น. ประเทศไทย ระบบจะจ่ายเฉพาะค่าคอมของออเดอร์สถานะ `COMPLETED` และตัวแทนที่เชื่อม User ID แล้ว สามารถทดสอบได้จากหลังบ้าน → `เครดิต ฝาก / ถอน` → `จ่ายค่าคอมตอนนี้`

## เปิด Web Push

หลัง Deploy ให้เปิด `/admin` บนอุปกรณ์แอดมิน กด `🔔 เปิดแจ้งเตือน` และอนุญาตการแจ้งเตือน จากนั้นกด `⚡ ทดสอบ` ได้ทันที บน iPhone/iPad ต้องเพิ่มเว็บไว้ที่หน้าจอโฮมและเปิดจากไอคอนนั้นก่อน

## การเปิดหลังบ้านครั้งแรก

1. Deploy ระบบให้เรียบร้อย
2. ใช้อุปกรณ์แอดมินหลักเปิดหน้าร้าน
3. กดดาวเคราะห์และรอวาร์ป 3 วินาที
4. ระบบจะสร้าง User ID และกำหนดอุปกรณ์นี้เป็น `OWNER` โดยอัตโนมัติ

หลังมี OWNER แล้ว อุปกรณ์ใหม่จะเริ่มต้นเป็น `CUSTOMER` และไม่สามารถเปิดหลังบ้านได้เอง การล้างคุกกี้ของอุปกรณ์ OWNER จะทำให้รหัสอุปกรณ์เดิมหาย จึงควรใช้เบราว์เซอร์หลักเดิมจนกว่าจะเพิ่มหน้าจัดการอุปกรณ์สำรองในรุ่นถัดไป

ตรวจการเชื่อมฐานข้อมูลได้ที่ `/api/health` ซึ่งควรตอบข้อมูลที่มี `{"ok":true,"database":"connected","version":"5.13.0"}`

> สำคัญ: หลัง Deploy ใหม่ ให้ใช้อุปกรณ์แอดมินหลักเปิด `/admin` เป็นอุปกรณ์แรกและอย่าล้างคุกกี้ของอุปกรณ์นั้น ระบบไม่ใช้หน้าล็อกอินตามข้อกำหนด จึงผูกสิทธิ์กับคุกกี้อุปกรณ์หลัก
